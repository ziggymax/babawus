# Babawus (BAsic BAckup With Usb Storage)

Babawus is a (fairly) simple application for backing up folders from a hard disk to a USB storage device, typically a USB stick. It is, at least initially, intended only for a Linux desktop environment.

## General use case and concept

### Use case - The KISS of backup systems

The primary purpose of Babawus is to make it very easy for a non-technical person to maintain a backup of important files and folders:

1. The user inserts an usb stick in their computer
2. The user clicks on the Babawus icon
3. Babawus starts, recognizes that a Babawus-enabled usb storage medium is present and copies relevant files and folders to the medium
4. Babawus presents the user with a status message

That's it.

### Preparing an usb medium for use with Babawus

A USB stick (or other USB storage medium) is prepared for use with Babawus by placing a text file named `babawus_drive.cfg` in its top folder. The file contains:
    - A header with a marker that identifies the medium as a Babawus medium.
    - Configuration: which folders to back up, and where to put the backups on the medium.
    - Some sort of validation marker that indicates that the file has previously been checked for syntax and correctness

The user uses Babawus to prepare the medium.Without going into low-level details here are some thoughts on the configuration file:

1. The file is always called babawus_drive.cfg and it is the only file Babawus needs to look for
2. In the first part of the file (header) there is some fixed boiler plate text that explains what the file is and warns against deletion
3. The the second part of the file there is some confguration such as:
    - Which target folders to backup/copy and where to put them on the usb media
    - Exclude patterns/wildcards that specifies files and folders NOT to be copied
4. Finally there is some kind of (verifiable) marker/checksum at the end of the file indicating that the file has been generated by Babawus and is valid.

### Copying, not mirroring

Babawus copies; it does not mirror.

- Files in the source folders are copied to the medium. A newer version of a file overwrites the older copy on the medium.
- Files deleted from a source folder are never deleted from the medium.
- Only one version of each file is kept. If a damaged or unwanted version of a file is copied, it overwrites the good copy. This risk is accepted.

### Handling of the medium

Using a medium with Babawus is the same as using it without Babawus. The medium is mounted automatically by the system when it is inserted, and the user ejects it explicitly before physically removing it. Babawus neither mounts nor ejects media.

## General requirements and doctrines

1. The application must present a very simple and easy-to-use graphical interface. This is not an objective requirement, but the point is that the application should be easy to use for someone who is almost computer-illiterate but can manage start it by inserting a usb stick and clicking an icon titled "Backup". That means a user interface with few buttons, fly-by help on all visible elements, no hidden state or context-dependent UI elements, liberal use of good icons and graphics, and solid, friendly feedback on all relevant user actions.
2. The application should be kept as simple as possible.
3. The application should have as few dependencies as possible. Don't pull in external libraries or frameworks for functionality that can be coded natively in a handful of lines. But using some sort of UI framework is obviously necessary.
4. All non-gui (logic) parts of the application must be covered by tests.
5. Testability and robustness are more important than architectural finesse.
6. While the initial target platform is Linux Mint, the application should aim for compatibility with all modern Linux distributions.
7. The application must be easy to install and uninstall, for example through custom scripts or platform-relevant package formats.

## Specific includes and excludes

### Includes

The application must allow the user to:

1. Start a backup to a mounted USB medium that contains a valid `babawus_drive.cfg` file.
2. View the history of Babawus usage for a medium. Each run logs basic data to a file on the medium (date and time of start and completion, number of source files scanned and copied, files skipped due to errors, data consumption, etc.). The application must make it easy to view this log.
3. View the status of mounted USB media with respect to Babawus, i.e. whether each is set up for use with Babawus.
4. Initialize a USB medium for use with Babawus by creating a properly formatted `babawus_drive.cfg` file.

Include 1 is the most important use case. The initial UI (the one shown right after start) should only offer starting a backup, viewing the history and see status (includes 1-3). Include 4 id reached through a separate "Advanced" menu item or button. This conflicts somewhat with the "no context-dependent UI elements" doctrine, but it makes it harder for a non-technical user to wander into functions that may cause problems.

### Excludes

- **Restore.** Babawus provides no restore function. To restore, the user simply mounts the medium and copies the wanted files or folders from it by hand, to wherever they want them.
- **Deletion on the medium.** Babawus never deletes files from the medium because they were deleted from a source folder.
- **Versioning.** Babawus keeps only the latest copied version of each file.
- **Mounting and ejecting.** These are left to the system and the user.
